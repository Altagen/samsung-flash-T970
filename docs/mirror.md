Every third-party file this project needs is pinned (exact version and SHA-256 in
[`SHA256SUMS`](../SHA256SUMS)) and **downloaded from its official source**.
Links break, though: nightly builds move, XDA attachments vanish, firmware mirrors
close. So the project keeps a **backup copy** of each file in the GitHub release
[`v1.0.0`](https://github.com/Altagen/samsung-flash-T970/releases/tag/v1.0.0)
(the release also carries the "Warranty Void" presentation as a single HTML file).

> [!IMPORTANT]
> Prefer the official sources. The mirror is a fallback. In both cases the
> checksum is verified: a file that does not match `SHA256SUMS` is rejected,
> whatever its origin.

## How the scripts use it

`scripts/lib/fetch.sh` (used by `scripts/fetch-downloads.sh` and every
installer) does, for each file:

1. download from the **official URL**, then check the SHA-256;
2. if the download fails, or the file differs (e.g. a nightly that moved on),
   download from the **mirror**, then check the SHA-256;
3. if neither source matches, stop with an error.

```bash
scripts/fetch-downloads.sh            # everything into downloads/, verified
scripts/fetch-downloads.sh --list     # names
```

Kernel sources come from git (`kernel/get-sources.sh`, pinned commit), with the
mirror archive as the fallback.

## For maintainers: (re)publishing the release

```bash
scripts/fetch-downloads.sh                                   # all files present and verified
git -C sources archive --prefix=android_kernel_samsung_sm8250-4910fe83f/ 4910fe83f91f340e28ada2c956a5ca39676dc619 \
    | xz -T0 -6 > downloads/android_kernel_samsung_sm8250-4910fe83f.tar.xz   # if missing
firmware/make-vbmeta-disabled.sh
sha256sum -c SHA256SUMS

R=output/release-v1.0.0; mkdir -p $R
cp downloads/* firmware/vbmeta_disabled.img $R/
cp docs/research/presentation/warranty-void.html $R/
cp docs/research/presentation/warranty-void.html /tmp/presentation-void-warranty.html
tar --owner=0 --group=0 -C /tmp -czf $R/presentation-void-warranty.tar.gz presentation-void-warranty.html
(cd $R && sha256sum $(ls | grep -v SHA256SUMS) > SHA256SUMS)

gh release create v1.0.0 --title "v1.0.0" --notes-file docs/release-notes-v1.0.0.md $R/*
```

When a pinned version changes: update `SHA256SUMS`, the URL in
`scripts/lib/fetch.sh` and this table, publish a new release, and point
`MIRROR_BASE` in `scripts/lib/fetch.sh` to it.
